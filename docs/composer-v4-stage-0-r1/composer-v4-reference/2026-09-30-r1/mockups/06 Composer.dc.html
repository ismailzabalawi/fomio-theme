Composer · v4

Design awaiting your approval · not for implementationRevision r1 · 2026-09-30 · audit corrections (handoff §12)

v4 keeps the v3 direction: one native Discourse composer, touch first, with the Photo / Format / More entry points. It adds named frames and prototype routes for the cases the audit found thin: tablets, links, quotes, drafts, permissions, advanced inserts, completion, the conditional guided form, uploads, and accessibility. Every frame is a live instance of the prototype component. Nothing here changes Discourse; implementation starts only after you approve and lock the design.

IA and state transitions

The composer is one surface whose state is described on independent axes. Changing one axis never resets another: rotating a tablet does not cancel an upload, a failed draft save does not block publishing, and a rejected submission leaves the draft, uploads and text untouched. The prototype shows the current value of every axis beside the frame.
